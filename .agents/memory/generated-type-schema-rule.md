---
name: Generated Type Schema Rule
description: When adding fields to productsTable, four generated type files must all be updated together, or TypeScript errors appear across the frontend.
---

## Rule
Any new column added to `productsTable` (lib/db/src/schema/products.ts) must be propagated to all four generated type files manually, then each package's declarations rebuilt with `npx tsc -p tsconfig.json`.

## The four files
1. `lib/api-client-react/src/generated/api.schemas.ts` — `Product`, `CreateProduct`, `UpdateProduct` interfaces (source)
2. `lib/api-client-react/dist/generated/api.schemas.d.ts` — same interfaces (declaration emit, must match src)
3. `lib/api-zod/src/generated/types/product.ts` — `Product` interface
4. `lib/api-zod/src/generated/types/createProduct.ts` — `CreateProduct` interface
5. `lib/api-zod/src/generated/types/updateProduct.ts` — `UpdateProduct` interface

Also update the `mapProduct()` function in `artifacts/api-server/src/routes/products.ts` so the API actually returns the new field, and add it to the POST/PUT Zod validation schemas in that same file.

**Why:** These files are generated by orval from an OpenAPI spec. The spec hasn't been regenerated — the files are hand-edited. Forgetting any one of them causes `Property 'x' does not exist on type 'Product'` errors across the frontend.

**How to apply:** After every productsTable column addition, grep for `interface Product` across lib/ and update all occurrences, then rebuild both packages.
